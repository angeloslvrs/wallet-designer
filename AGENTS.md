# AGENTS.md

Canonical guidance for AI coding agents (Claude Code, Codex, Cursor, Gemini CLI, …) working in this repository. `CLAUDE.md` imports this file — edit here so every agent sees the same instructions.

## What this is

Designer + server for Apple Wallet airline boarding passes (including iOS 26 `semantics` expanded-view fields). Builds real, signed `.pkpass` files and implements the Apple PassKit Web Service so installed passes can be updated via APNs push.

**`HANDOFF.md` (repo root) is the cross-session context doc** — decided direction, do-not-break invariants, environment state (deploy box, cert status), backlog, and dated session entries. Skim its "Start here (next session)" section before substantive work, and append a session entry when you finish some (the repo's established habit). The full HTTP route table lives in `README.md` — don't duplicate it here.

## Commands

```bash
npm install
cp .env.example .env
npm run init                # one-time: generates self-signed dev cert + placeholder assets (required before any build)
npm run dev                 # designer SPA on :4318 (Vite) + API on :4317 (Express), via scripts/dev.js

npm test                    # vitest run (tests live in tests/ at repo root; DOM tests set @vitest-environment happy-dom per file)
npx vitest run tests/manifest.test.js   # single test file
npm run check               # validate all fixtures/ against the JSON schema

npm run build:pass -- --in fixtures/fully-loaded.json   # headless FormState build → out/*.pkpass (--now [--lead 60] shifts the schedule to now)
npm run build:pass -- --template dev-sample             # headless template-path build (--serial, --data data.json)
npm run validate:apple      # Apple buildpass validators; exits 0 with a skip note if no binary (CI is the real gate)
node scripts/field-coverage.mjs   # regenerate docs/field-coverage.md from apple/pass-builder protos
npm run build:designer      # production SPA bundle → apps/designer/dist
npm start                   # production mode: one Express process serves built SPA + API on :4317
npm run cert:inspect        # inspect the active signing cert
```

Node >= 24 (the store uses built-in `node:sqlite`). Everything is ESM (`"type": "module"`) vanilla JavaScript — no TypeScript, no frontend framework — and stays that way: minimal dependencies, no framework creep.

## Architecture

npm-workspaces monorepo (`apps/*`, `packages/*`):

- **`packages/pass-schema`** — JSON Schema + JSDoc typedefs for `FormState`, the single source of truth for the pass data model shared by designer, server, and builder.
- **`packages/pass-builder`** — the core pipeline: `form-to-pass.js` (`formStateToPassJson`), `template.js` (load a `.pkpasstemplate` bundle + merge per-pass data by field key), `template-zip.js` (sanitize uploaded template zips), `manifest.js` (SHA1 manifest), `sign.js` (PKCS#7 detached signature via node-forge), zipped into `.pkpass` with archiver. Around the core: `semantics.js` (Apple's fixed boarding vocabulary + emit helpers), `bindings.js` (per-template binding discovery), `field-kinds.js` (semantic → validation kind), `bcbp.js` (IATA boarding-pass barcode parser), `expiry.js` (derives the `relevantDates` interval + `expirationDate` from the flight schedule; blank expiry = arrival + 1 day), `validate.js` (FormState schema check). `migrate.js` is a frozen legacy emitter powering FormState migrations — round-trip fidelity depends on it staying byte-identical; do not "improve" it.
- **`apps/designer`** — Vite SPA on the "Studio dark" visual system (spec: `docs/superpowers/specs/2026-10-09-ui-overhaul-studio-dark.md`; clickable reference prototype `docs/mockups/f-studio-dark.html`): iOS-dark tokens in `styles.css` `:root` with a light theme on the same tokens (`[data-theme=light]`, toggle in the masthead, `theme.js`), Inter + JetBrains Mono, rounded cards, one blue primary per screen. The legacy `--wpd-*` tokens are gone; the remaining `wpd-*` class names belong to the Design editor's form internals (`form.js`) and are styled on the theme tokens. Views wired in `main.js` behind a segmented masthead nav (Flights · Templates · Device log); Issue and Design are full-screen workspaces entered from the Templates shelf (`#app-shell.is-workspace` hides the nav); **Flights is the landing view** (`flights.js`: departures board, one row per trip, plus a docked control panel that pushes typed status updates flight-wide or per pass — this replaced the old Manage view). `log.js` is the Device log page. Views are code-split — dynamic `import()` on first show, and the recorded `activeView` keeps a stale import from mounting over a newer selection; `#<view>` in the URL deep-links a view. `templates.js` is the Templates shelf (Pass Designer bundles from `GET /api/templates` and Studio designs from `GET /api/studio-templates` (saved in `designs/`) on one shelf, Apple-faithful thumbnails via the wallet preview renderer with the barcode stubbed so bwip-js never loads there) plus the Bindings review screen (upload lands on it; Confirm PUTs the map, which marks every entry `manual`/`high`; `needsReview` flags only date-proximity/seat-composite matches and value matches whose field key shares no word with the semantic, so key-identical pairs like `departureGate → gate` are "matched", not alarms). Studio cards Delete via `DELETE /api/designs/:name`; `fixtures/` holds CI's tracked regression fixtures, is read-only over HTTP (`?fixture=` deep links), and never appears on the shelf. The overhaul phases 1–5 are done (spec "Phases"). **Design** (`design.js` + `form.js`, one section at a time: Look · Fields · Flight data · Barcode · Advanced; Save template → `designs/`; Issue passes → saves then opens Issue; the old Build .pkpass issue path is gone; `?fixture=` opens a CI fixture as an unsaved copy): form (`form.js`/`inputs.js`/`semantics-editor.js`) + tabbed preview (`src/preview/wallet/` renders the faithful Wallet-style preview), BCBP autofill from a scanned/pasted boarding-pass barcode (`scan.js`, `bcbp-preview.js`; paste → upload → camera), branding-image upload slots (PNG data URLs only). **Issue** (`issue/`): a full-screen workspace entered from a template card (either kind; the masthead nav hides, `‹ Templates` leaves) — Flight (shared values) → Passengers (three panes: scan-first multi-line BCBP paste / Type / Roster + list | Apple-faithful pass | this passenger's fields + serial) → Issued (QR grid, Wallet badge, Copy all links, Open flight selects the trip on the board). `issue/model.js` is the pure, tested core and is **semantics-first**: each template field bound to a semantic is edited through that semantic (typed: names, seats, ISO dates, IANA zones; date and time-zone twins collapse into one slot that writes both spellings) and its visible value is derived; unbound fields are raw by key. Studio designs ship the same merge surface from `GET /api/studio-templates` (confirmed bindings when the operator saved some — `studio:<name>` in `template_bindings`, `PUT/DELETE /api/designs/:name/bindings`, Bindings action on Studio cards — else discovered live from the design's own sample values; the entry ships the *unresolved* binding surface, see label tokens below), so one code path builds both bodies: `{template, serialNumber, groupId, data}` or a FormState + envelope `designName` (stored in `passes.design_name`, counted on the shelf). Per-passenger slots never ship a template's sample values (blank → cleared); a blank shared slot keeps the template default (shown as the placeholder). Schedule times default to the airport zone's offset (`zoneOffset` in `inputs.js`), not the browser's. Errors appear on blur or Issue only; the footer carries readiness and the one primary, labelled honestly ("Issue 1 · update 1"); suggested serials skip ones already issued; in-batch duplicates block. **Flights** (`flights.js`/`ops.js`): the ops board — `GET /api/passes` folded into one row per trip (`flightsFrom`, which also derives the trip-level live values the editor shows as placeholders/"now …" hints), status pills (a pass with `statusSet: false` shows "Not pushed", never a fabricated On Time), control panel with toggle-style status keys (pressing the active key = no change) + reason + gate visible and the schedule/rarely-used fields behind disclosures, group and per-pass push with button states (Pushing… → ✓) and a shell toast (`toast.js`), confirmed Clear/Delete, Add-to-Wallet. Narrow layouts stack the panel under the board and scroll it into view on row tap. View mounts abort the previous mount's listeners on re-mount (`root._mountAbort`) — keep that pattern or tab switches stack duplicate handlers. The Add-to-Wallet badge is Apple's official artwork (`wallet-badge.js` + committed SVG), used verbatim per Apple's guidelines: never recreate, recolor, or restyle it; hide — never dim — it when there's no URL.
- **`apps/server`** — Express API. Routes: `build.js` (build/download), `designs.js` (saved Studio designs — FormState snapshots in gitignored `designs/`; distinct from `.pkpasstemplate` templates), `fixtures.js` (read-only CI fixtures), `admin.js` (issue passes, status + push triggers, saved-passenger roster: `GET/POST /api/roster`, `DELETE /api/roster/:id`), `templates.js` (upload/list/delete `.pkpasstemplate` bundles; DELETE 409s while any stored pass references the template), `wallet.js` (Apple PassKit Web Service `/v1/*`, rate-limited). `apns.js` sends outbound push to `api.push.apple.com` (HTTP/2 with reconnect + retry and 410 pruning; logs instead of pushing under the dev profile). `storage.js` is a SQLite store (`state/passes.sqlite`, built-in `node:sqlite`; one-time imports a legacy `state/passes.json` on first boot) for issued passes, device registrations, a bounded device log, template bindings, and the roster. `pass-build.js` turns a stored record into a signed `.pkpass` (branches FormState vs template). `template-status.js` maps the status-update vocabulary onto template data.

### Two build paths

Stored passes come in two shapes, both rebuilt at fetch time by `apps/server/src/pass-build.js`:

- **FormState** (`rec.state`) — the designer flow; `formStateToPassJson`.
- **Template** (`rec.template` + `rec.data`) — issue with `POST /api/passes {template, serialNumber, data, groupId}` against a bundle in `templates/<id>.pkpasstemplate/`. `data` addresses template fields **by key**; reserved keys: `semantics` (deep-merge; a `null` value DELETES the key — how issue-time clears placeholder semantics), `additionalInfoFields` (append/replace-by-key), `barcodeMessage`/`barcodeAltText`. Unknown keys fail at issue time (dry-run merge). `serialNumber`/`authenticationToken`/`webServiceURL`/`passTypeIdentifier`/`teamIdentifier` are always injected server-side, never trusted from a template.

### Semantics vs field keys (polarity rule)

Semantic tags are **Apple's** fixed vocabulary (boarding subset hardcoded in `packages/pass-builder/semantics.js` as `BOARDING_SEMANTICS`); field keys are the **designer's** arbitrary per-template vocabulary. NO code assumes template key names — each template gets a discovered `semanticKey → fieldKey` binding map (`packages/pass-builder/bindings.js`), persisted in SQLite (`template_bindings`), recomputed on upload, editable via `PUT /api/templates/:id/bindings` (Templates card). The status API vocabulary is semantic keys on both pass shapes (legacy verbs `gate`/`boarding`/`depart`/`arrive`/`transitInfo` are route-layer aliases). Unbound semantics still update — iOS 26 renders `semanticBoardingPass` from semantics directly — and `skippedFields` in status responses reports unbound keys only on passes that are NOT semantic-driven (on a semantic pass nothing was actually skipped). Issue-time and status-edit validation derives each field's input kind through **bindings → semantics → kind** (`packages/pass-builder/field-kinds.js`; style attrs are the unbound fallback), never from field-key names: `GET /api/templates` ships the descriptors, the UI blocks invalid submits inline, and the server independently 400s malformed provided values. At issue time, volatile template placeholders (the six schedule dates, `passengerName`, `seats`) are null-cleared unless re-derived from bound data; `tooling.json` and `_id` never reach an emitted pass (bundles on disk stay faithful to Designer's export). Time zones: emit **both** `*LocationTimeZone` (docs) and `*AirportTimeZone` (Designer/protos). Studio-only field extensions, resolved by `resolvePassFields` (`packages/pass-builder/field-render.js`, browser-safe — it ships in the SPA, so it imports `field-zones.js`, never `template.js`) at the end of `formStateToPassJson` and in the wallet preview's `toPassView`: label tokens `{semanticKey}` / `{semanticKey:upper}` fill a label from the pass's semantics, and `timeFormat: "24h"` fields store ISO (so Issue, bindings and status updates treat them as dates) and are rendered `HH:mm` from the string's own offset. Neither ever reaches an emitted pass.json; `formStateToPassJson(s, {resolveFields: false})` is the raw binding surface. Status updates on a pass issued from a design overlay the design's confirmed bindings on discovery (by `designName`). Image variants: Pass Designer exports only `@2x`/`@3x` scale variants (never the 1x base), but iOS rejects "Add to Wallet" without a base `icon.png` — so `ensureBaseImageVariants` (`template.js`) synthesizes any missing base from the `@2x` (else `@3x`) bytes at emit time (standard slots only — Designer's non-rendered `primaryLogo` is left alone; on-disk bundle stays faithful). `templates/cebpac.pkpasstemplate` is a real Pass Designer 1.0 export; `templates/dev-sample.pkpasstemplate` is the hand-written second naming convention exercising the same bindings path.

### Status updates & push behavior

Updating a pass = mutate stored state, bump `lastModified`, send an **empty** APNs notification; devices re-fetch, and `GET /v1/passes/...` rebuilds the `.pkpass` from stored state at fetch time (both shapes). Status changes update the visible bound field AND auto-attach a `changeMessage` in lockstep with the semantics (both shapes; an explicit `{value, changeMessage}` from the caller wins). Wallet web-service status codes (201/200/204/304/401/404) are spec-mandated — devices depend on them exactly. On-device (verified on iOS 26): **semantic** passes surface status changes via the Lock-Screen **Live Activity**, not `changeMessage` banners; classic passes get the banner. The Live Activity is wanted — `associatedStoreIdentifiers` would suppress it and is deliberately not used; don't add it.

### QA gates

Two workflows run on every push to `main` (`.github/workflows/`):

- **`node-ci.yml`** — Node 24 regression gate: `npm test`, `npm run check`, the SPA build, and a headless build of both stored-pass shapes.
- **`apple-validate.yml`** — builds a pass from `dev-sample` headlessly, unzips it, and runs Apple's `buildpass validate` (built from `apple/pass-builder` at a **pinned SHA** — `PASS_BUILDER_SHA` in the workflow). `scripts/field-coverage.mjs` reads protos at the **same SHA**; bump both together. `validate` checks structure/semantics only (no signature verification), and validation errors fail CI — `templates/dev-sample.pkpasstemplate/pass.json` carries sample semantics specifically to satisfy `BoardingPassValidator`; per-pass data overrides them at issue time.

### Cert profiles

`CERT_PROFILE` in `.env` selects `certs/dev/` (self-signed, from `npm run init`; passes build but won't install on iOS) or `certs/prod/` (real Apple Pass Type ID cert — signs passes **and** authenticates to APNs; see `docs/cert-day.md`). With `CERT_PROFILE=prod` the server refuses to boot unless `WEB_SERVICE_URL` is a valid `https://` URL (`env-validate.js`) — on a box whose `.env` pins prod, run `CERT_PROFILE=dev npm run dev` for local work. `npm run build:pass` signs too, so it likewise requires `CERT_PROFILE=dev` (dev certs come from `npm run init`) unless real prod certs are present. Prod certs, `.env`, and `state/` are gitignored and live only on the deploy box. The server forces `passTypeId`/`teamId` from env onto every issued pass.

### Security model (don't break these invariants)

- `apps/server/src/middleware/guard.js` is the access boundary: `/api/wallet/*` is **public** (Apple devices call it from the internet; each request is authenticated per-pass with the `ApplePass {authenticationToken}` header, compared timing-safely). **Everything else** (SPA, `/api/build`, `/api/passes`, `/api/fixtures`, `/api/roster`, `/api/templates`) is the control plane — private-IP/LAN only, or admin Basic Auth (`ADMIN_USER`/`ADMIN_PASSWORD` env). Depends on Express's trust-proxy setting: `TRUST_PROXY=<ip|cidr>` in env pins `X-Forwarded-For` trust to the actual reverse proxy (prod sets the NPM LXC's IP; see `docs/deploy.md`); unset falls back to `1` (any single hop — dev only).
- No CORS on purpose — SPA is same-origin with the API, and PassKit calls are server-to-server. Don't add a wildcard.
- A pass's `authenticationToken` must stay **stable per serial** across re-issues — including across FormState ↔ template shape changes — rotating it 401s copies already installed on devices (see `storage.js`).
- **Server-controlled pass identity (both shapes).** `serialNumber`/`passTypeIdentifier`/`teamIdentifier`/`authenticationToken`/`webServiceURL` are forced server-side in `pass-build.js` for **both** FormState and template passes — never trusted from the stored state or the template bundle. `webServiceURL` in particular **must be HTTPS** (from the `WEB_SERVICE_URL` env): a pass that still carries the designer's dev default `http://localhost:4317/api/wallet` is rejected by iOS at install. (Regression once shipped: FormState passes skipped this override, leaked the localhost URL, and couldn't be added to Wallet.)
- All token/credential comparisons go through `src/util/timing-safe.js`; user-supplied strings in the designer go through `src/esc.js` before hitting innerHTML.

### Production deploy (LXC)

In production a single Express process serves the built SPA from `apps/designer/dist` and the API on one port, so one origin covers the UI, `/api`, and the pass `webServiceURL` callbacks. The dist bundle is gitignored — build locally with `npm run build:designer` and rsync it; the box runs prod deps only (no Vite). Full runbook (LXC + Nginx Proxy Manager + pm2, redeploy steps, caching gotchas): `docs/deploy.md`.

- **The box**: LXC at `root@10.1.2.237`, app dir `/opt/boardingpass`, pm2 process `boardingpass`, port 4317, public URL `https://boardingpass.geloflix.com`. It's reachable only when the VPN/route is up — `ssh: No route to host` means the VPN is down: **stop and ask the user**; don't burn commands diagnosing ssh config.
- **No git on the box** — deploys go via rsync: ship `apps/server/` and `packages/pass-builder/` (exclude `.env` and `node_modules`; also `packages/pass-schema/` and the rebuilt `apps/designer/dist/` if touched — exact commands in `docs/deploy.md`), then on the box `npm install --omit=dev` (if deps changed) and `pm2 restart boardingpass`.
- **Verify after deploy**: `curl https://boardingpass.geloflix.com/api/profile` (health), and shasum-compare a deployed hashed asset against the local `apps/designer/dist` copy.
